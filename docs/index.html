Soundcore headphones,
controlled from macOS

Anker ships the app for phones only. This talks to the headset directly over its own Bluetooth protocol — every byte worked out by watching real traffic, and checked by reading the value back off the hardware.

Install Source
// the bytes that switch noise cancelling on
08 EE 00 00magic00seq06 81cmd10 00len00 5F 02 00 00 01payloadEFsum

Sixteen bytes on RFCOMM channel 30. The headset ignores every one of them until a handshake runs first — which took a day to discover.

§01

What it does

Everything the phone app does, minus the phone.

Noise control

06:81

Noise Cancelling, Transparency and Normal, plus ANC strength 1–5 — which the official app reads back incorrectly, showing its own cached value instead of the headset's.

Equaliser

03:87 · 53-byte frame

All 22 factory presets and a custom 8-band curve at ±6 dB, including the DSP compensation tail the firmware expects.

Device state

01:01 · 103 bytes

Battery, firmware, model and multipoint host count, polled live and decoded through a per-model profile.

Command line

soundcorectl

Scriptable control, plus the probe, sweep and diff tools used to map the protocol in the first place.

Safe by default

ch 12 · ch 13 blocked

Firmware-flashing channels are refused by service identity, so the guard holds on every device rather than only the one it was written on.

§04

Install

Homebrew refuses untrusted third-party casks, so the middle line is required. The app is ad-hoc signed rather than notarised, which is what --no-quarantine handles. macOS 13 or later.

$ brew tap mervin008/tap
$ brew trust mervin008/tap
$ brew install --cask --no-quarantine mervin008/tap/soundcorebridge
# build it yourself
$ git clone https://github.com/mervin008/soundcorebridge
$ cd soundcorebridge && ./make-app.sh
# or drive it from a script
$ soundcorectl anc nc --level 5
$ soundcorectl eq "6,4,2,0,0,-2,-4,-6"
§05

Compatibility

Unknown models stay read-only on purpose. Field offsets differ between models, and writing guessed offsets to unverified hardware is how devices end up in strange states.
