Why

Anker ships the Soundcore app for Android and iOS only. Plug the headphones into a Mac and you lose ANC control, the equaliser, and any idea of the battery level — even though the headset is perfectly happy to be told what to do over Bluetooth.

Features

Noise control

Noise Cancelling, Transparency and Normal, with ANC strength 1–5.

Equaliser

All 22 factory presets plus a custom 8-band curve, ±6 dB.

At a glance

Battery, firmware and multipoint status, tinted by listening mode.

Scriptable

A CLI for automation, plus the tools used to map the protocol.

Unknown models stay read-only on purpose. Field offsets differ between models, and writing guessed offsets to unverified hardware is how devices end up in strange states.

Install

$ brew tap mervin008/tap
$ brew trust mervin008/tap
$ brew install --cask --no-quarantine mervin008/tap/soundcorebridge

Homebrew requires third-party casks to be trusted explicitly, hence the middle step. The app is ad-hoc signed rather than notarised, which is what --no-quarantine handles. Requires macOS 13 or later.

Build from source

$ git clone https://github.com/mervin008/soundcorebridge
$ cd soundcorebridge && ./make-app.sh
$ open build/SoundcoreBridge.app

CLI

$ soundcorectl status                  # battery, firmware, ANC, EQ
$ soundcorectl anc nc --level 5
$ soundcorectl eq rock
$ soundcorectl eq "6,4,2,0,0,-2,-4,-6" # custom curve, dB per band

How it works

RFCOMM ch 30  →  frame codec (08EE/09FF + checksum)  →  device profile  →  UI

The frame format is the same across Soundcore models. What changes per model is where fields sit in the state blob, which value means which sound mode, and how many EQ bands there are — so adding a device is a profile, not new protocol code.

Two things cost real time to find: writes are silently ignored until a handshake runs, and the first RFCOMM open in a process always fails — it primes IOBluetooth’s run loop and the callback never arrives. Both are documented in the protocol map.
