Features

Everything the phone app does, in your menu bar

Every value here was confirmed by reading it back off real hardware. Nothing is guessed.

Noise control

Noise Cancelling, Transparency and Normal — plus ANC strength 1–5, which the phone app itself displays incorrectly.

Equaliser

All 22 factory presets and a custom 8-band curve at ±6 dB, with the DSP compensation the firmware expects.

Battery & state

Battery, firmware and multipoint host count, polled live.

Scriptable

A CLI for automation, and the tools used to map the protocol.

Safe by default

Firmware-flashing channels are blocked by service identity, on every model.

Compatibility

Verified hardware, not a wishlist

Unknown models stay read-only on purpose. Field offsets differ between models, and writing guessed offsets to unverified hardware is how devices end up in strange states.

Install

Two commands and a trust step

Homebrew refuses untrusted third-party casks, so the middle line is required rather than optional. The app is ad-hoc signed rather than notarised, which is what --no-quarantine handles. macOS 13 or later.

$ brew tap mervin008/tap
$ brew trust mervin008/tap
$ brew install --cask --no-quarantine mervin008/tap/soundcorebridge
# build from source
$ git clone https://github.com/mervin008/soundcorebridge
$ cd soundcorebridge && ./make-app.sh
# or drive it from the shell
$ soundcorectl anc nc --level 5
$ soundcorectl eq "6,4,2,0,0,-2,-4,-6"
How it works

One codec, many devices

The pipeline

RFCOMM ch 30 → frame codec (08EE/09FF + checksum) → device profile → UI

The frame format is identical across Soundcore models. What changes is where fields sit in the state blob, which value means which sound mode, and how many EQ bands exist — so adding a device is a profile, not new protocol code.

Two hard-won facts

Writes are silently discarded until a handshake runs. And the first RFCOMM open in a process always fails — it primes IOBluetooth's run loop and the callback never arrives. Both are in the protocol map.

The interface is tinted by listening mode — blue for ANC, teal for Transparency.
